Rank buildings by occupied GT voxel count, breaking ties by scene ID in Unicode lexicographic order. Divide the ranks into five strata of 20. Independently shuffle each stratum with seed `20261013` using `sha256-counter-rejection-fisher-yates-v1`: SHA256 of the UTF8 version, seed and domain separated by NUL, followed by the decimal counter; reject draws outside the largest multiple of the integer draw bound below `2**256`; run backward Fisher–Yates. The full disabled evaluation plan has 180 O, 180 J, 60 P and 60 E inputs per Builder: 480 each, 960 combined. P/E are each one record per building, never replicated by description model. Executor control C is a separate CPU check and never counted as Builder success.

O is the saved description record, preserving original UTF8 text, original metadata, and any original building filename. J changes object key order and JSON whitespace only. It rejects duplicate keys and preserves the full typed tree, exact integer/decimal values, boolean/null distinctions, array order, all fields and uncertainty text. Source and typed-tree SHA256 bind the transformation. It does not recreate historical ARR canonicalization or assert semantic interpretation equivalence. Ordinary provider requests contain only this text and the public common Builder prompt; manifest GT/bbox/origin/image/Oracle fields are excluded. Offline tests use sentinels in those fields for both providers and both O/J conditions.

P provides exact occupied dimensions, occupied world bbox, exact material set, and occupied voxel count. E provides the explicit GT palette and Z-run specification, including frame/origin. Both are diagnostic GT conditions. GT can reveal hidden interiors and openings unavailable in the original views. E also tests decoding and expanding RLE. These contrasts do not isolate pure language information loss. Storage NPY uses Y,X,Z axes and inclusive bbox minima; index `[yi,xi,zi]` maps to world `(xmin+xi,ymin+yi,zmin+zi)`. Original images/descriptions may not determine world origin, so absolute errors cannot be attributed solely to description ability.

All GT references must be nonempty. Exact-spec round trips and reference actions are checked against every material and world position under the configured executor limits. Every input reports its UTF8 byte count, common-prompt bytes, 1024 framing margin, context budget, output cap, and reference output size. No truncation is performed. The conservative input token estimate is a byte upper bound with an explicit uncertified wrapper/tokenizer assumption; a failure of that bound is labelled `NOT_FIT_CERTIFIED_BOUND`, not proof of actual token impossibility. Large exact reference output sizes do not prove infeasibility of every equivalent action representation; output completion is never guaranteed.

The shared evaluation version is `server_v2.2_strict_translation`: exact integer sparse/NTT maximum occupied overlap over all XYZ translations, with L1-minimum then XYZ-lexicographic tie break. Material and repair use the same occupancy-selected shift. No rotation, scale, coordinate clamping or GT-dependent prediction repair is added. Resource-limit outcomes remain unmeasurable. Absolute and aligned columns stay separate. The score is bounded in `[0,1]`; the strict translation search has no finite-radius restriction.

Primary metrics are aligned occupancy IoU and occupied bbox dimension MAE. Three separate families are predeclared: eight Anthropic-minus-OpenAI contrasts across O/J/P/E and two primary metrics; four J-minus-O contrasts across both Builders and two primary metrics; and eight P/E-minus-O diagnostic contrasts across both Builders and two primary metrics. Apply Holm within each entire family. Nonestimable comparisons retain null p-values and count as p=1 for correction, preserving family size. Secondary absolute IoU, material-set F1, material-aware IoU, add/delete/replace counts and normalized repair are descriptive with their own common-valid pair denominators and no extra significance claim.

Match ordinary provider comparisons by building and saved description provider. Compute matched differences within each building, average them within building, and weight buildings equally. Oracle-versus-O uses one Oracle value and the available ordinary-description mean per common building. Building-cluster percentile bootstrap uses 2000 replicates, the recorded seed and the same portable RNG; two-sided building sign-flip uses exact enumeration at at most 16 buildings and 10000 seeded Monte Carlo replicates otherwise, with plus-one p correction. The sign-flip test relies on exchangeability/symmetry of paired differences under its null. Retries are collapsed to one final outcome per input. Smoke has descriptive checks and failure counts, with no inferential or generalization claims.

Report valid-only conditional scores and a companion completed-request all-attempted IoU analysis. Failure0 is restricted to attempted, identified completed requests with known usage and definitive parse, validation, execution or truncation failures. A generic failed status or attempt ID is insufficient. Authentication, billing, model unavailability, context rejection, missing keys, transport problems and unknown usage are excluded as operational or unmeasurable and separately counted. NOT_RUN, budget stops, absent inputs/GT and alignment-resource failures are never assigned model failure0. Failed MAE and repair remain null; their paired comparisons use metric-specific common-valid subsets. Each group records denominators, failure classifications and independent building counts.
